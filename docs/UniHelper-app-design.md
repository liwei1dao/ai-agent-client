# UniHelper App 界面与信息架构设计（v2 · 标准助手版）

**项目名称**：UniHelper
**文档定位**：App 客户端界面重构详设——把 UniHelper 落地为"标准全能助手 App"。本文是 [UniHelper.md](UniHelper.md) §3「产品形态与信息架构」的细化与升级。
**版本**：v2.0
**日期**：2026-06-30
**状态**：方案稿

---

## 0. 产品角色：AI 助理 + 管家（最高指导思想）

UniHelper 的角色是用户的 **AI 助理 + 生活管家**：**主动接管用户的生活与工作**，替用户把每天安排好、把要紧事拎出来提醒、按需替用户办事。

由此推出一条统领全局的设计原则：

> **电话、日程、咨询、邮件、财务、健康……不是一个个"独立功能入口"，而是管家替用户打理的"生活领域/生活内容"。**
> App 不是让用户去"点功能"，而是管家把这些生活内容**主动汇报、主动安排、主动管理**。

这直接决定了首页形态（见 §3）：首页不是"工具宫格"，而是**管家的今日简报 / 生活概览面板**——以**信息输出**为主。

## 1. 本次重构的核心变化

1. **首页 = 全能助手聊天**：助理的**所有行为都以对话形式输出**；每日动态提醒、咨询等由各订阅**按模板主动推送到聊天里**。聊天顶部有 **今日待办 / 重要信息** 切换条。
2. **订阅 Tab（服务订阅）**：用户添加/管理订阅服务（咨询订阅、日程提醒、邮件巡检、财务月报、健康提醒、来电翻译…），本质是**"控制管家往聊天推什么"**——是 §8「调度引擎」的用户界面。
3. **生活 Tab（日程与生活管理）**：用户的每日日程时间线 + 生活管理（消费、健康、日程等）。
4. **我的 Tab = 设置中枢**：服务库、Agent 列表、通用设置都在此，参数全进二级页。
5. **底部仅 4 个 Tab：首页 / 订阅 / 生活 / 我的**（不再有独立"对话"Tab——首页即对话）。
6. **生活领域由"主动式管家服务"打理**：电话、咨询、日程、邮件、财务、健康等——**定时/事件触发、后台运行、把结果以推送/对话形式给到用户**，作为"生活内容"被管理，而非功能入口。

### 1.1 两类能力（关键概念）

| 类型 | 触发方式 | 例子 | 在产品中的呈现 |
|------|---------|------|------|
| **被动式（对话技能）** | 用户发起 | 对话、翻译、看图、文档问答、画图 | 在「对话」Tab 中由助手自动路由；复用现有 `agent_runtime` 管线 |
| **主动式（管家服务 / 生活领域）** | 定时/事件触发 | 电话、咨询、日程、邮件、财务、健康 | 作为"生活内容"被**主动汇报于首页、管理于动态**；后台调度引擎驱动，产出**记录**与**推送** |

> 主动式管家服务是这次的新骨架，它需要一套**调度/触发引擎 + 记录时间轴 + 推送**的支撑设施（见 §8）。用户不"打开功能"，而是管家替他把这些领域的内容打理好并汇报。

## 3. 💬 首页 · 全能助手聊天

首页就是**与全能助手的聊天界面**——这是 UniHelper 的核心理念：**助理的一切行为都以对话形式呈现**。被动问答、让它办事、各订阅的主动推送（晨间简报、资讯、提醒、邮件摘要…）都**作为消息出现在同一条聊天流里**。

```
┌─────────────────────────────────────┐
│ 🤖 UniHelper · 在线 · 你的全能管家  ⋯ │
├───────────────────────────────────────┤
│ [📋 今日待办 3] [⭐ 重要信息 2]        │ ← 顶部切换条（可点）
│  10:00 周会 · 15:00 牙医 · 交房租¥3800 │ ← 当前页速览
├───────────────────────────────────────┤
│  ┌ 🌅 晨间简报 ──────────── 08:00 ─┐  │ ← 模板化主动推送
│  │ 早上好！今天 5 件事，3 项需留意： │  │
│  │ 🔴 张总邮件「合同确认」需今天回复 │  │
│  │ 🟡 房租今天到期 ¥3,800           │  │
│  │ [让我回复邮件] [知道了]           │  │
│  └─────────────────────────────────┘  │
│  ┌ 📰 今日资讯〔咨询订阅〕── 08:00 ─┐  │ ← 订阅按模板推送进聊天
│  │ 精选 5 条：· 多模态模型… · 央行… │  │
│  │ [展开全部] [讲讲第1条]            │  │
│  └─────────────────────────────────┘  │
│              帮我把牙医改到明天同一时间│ ← 用户消息
│  ┌ UniHelper〔🔀日程〕────────────┐   │ ← 助手以对话执行
│  │ 已把牙医改到 7/1 15:00，提醒同步✓│   │
│  └────────────────────────────────┘   │
│  ┌ ⏰ 提醒 ──────────── 明天 14:30 ─┐  │
│  │ 该出发去牙医了，要我帮你叫车吗？  │  │
│  └─────────────────────────────────┘  │
├───────────────────────────────────────┤
│  [📎]   [🎤 按住说话]            [⌨️]  │ ← 多模态输入栏
├───────────────────────────────────────┤
│  💬 首页   📡 订阅   🌿 生活   👤 我的 │
└───────────────────────────────────────┘
```

设计要点：
- **对话即一切**：助理所有行为（问答、办事、汇报）统一以聊天消息输出，不存在割裂的"功能页"。
- **模板化主动推送**：晨间简报 / 资讯 / 提醒 / 邮件摘要等由调度引擎触发，按各自模板生成**特殊样式的助手消息**（带类型头部与时间、可带快捷动作），与普通对话气泡区分；每条推送标注来源订阅。
- **顶部 今日待办 / 重要信息 切换条**：常驻在聊天顶部，一眼看到当天要点；点击切换两个视图，点条目可在聊天中展开。
- **意图路由**：用户说需求，助手自动选用技能（翻译/看图/日程/文档…）并在气泡上标注所用技能，结果就地呈现。
- **多模态输入栏**：文字 / 语音 / 图片 / 文件，等价于悬浮助理单击唤起。
- **顶栏设备连接状态**：助手名称「UniHelper」后带一枚**设备状态芯片**（`🎧 已连接`绿 / `未连接`灰）。**未连接点击 → 进入设备扫描界面**（雷达扫描 → 发现设备列表 → 连接）。硬件设备（耳机/吊坠/眼镜等，复用 `device_manager`/JieLi BLE）由此配对；连上后作为一个"硬件 agent"经适配器纳入团队（见 [UniHelper-agents-protocol.md](UniHelper-agents-protocol.md) §0.1、§10）。

## 4. 📡 订阅 Tab · 服务订阅

用户在此添加/管理**订阅服务**，本质是**配置"管家定时或触发时往聊天推送什么"**——即 §8「调度/触发引擎」的用户界面。

```
┌─────────────────────────────────────┐
│ 订阅                          [＋添加]│
│ 管家会按下列订阅，定时/触发时把内容主动 │
│ 推送到「首页」聊天里。                  │
├───────────────────────────────────────┤
│ 📰 咨询订阅   每日08:00·AI/财经/科技 [●]│
│ 📅 日程提醒   到点提醒·提前15分钟    [●]│
│ 📧 邮件巡检   每30分钟·仅重要推送    [●]│
│ 💰 财务月报   每月1日09:00·含建议    [●]│
│ ❤️ 健康提醒   久坐/喝水/作息         [○]│
│ 📞 来电翻译   来电自动进入(需授权)    [○]│
├───────────────────────────────────────┤
│  💬 首页   📡 订阅   🌿 生活   👤 我的 │
└───────────────────────────────────────┘
```

- 每条订阅 = 一个主动式管家服务的"推送规则"：图标 + 名称 + 频率/规则 + 开关，点击进入详细配置。
- 关闭某订阅即停止其推送；新增订阅从模板库选择（咨询/日程/邮件/财务/健康/通话…）。

## 6. 👤 我的 Tab · 设置中枢

设置首页只做分组导航，所有参数进二级页；**服务库与 Agent 列表移入此处**。

```
┌─────────────────────────────────────┐
│ 我的                                  │
│ 👤 李伟                  记忆与偏好 > │
├───────────────────────────────────────┤
│ 助手与能力                            │
│  🤖 助手管理（启用 / 配置 / 排序）  > │
│  🧩 Agent / 技能配置               > │  ← 原首页 Agent 列表移入
│  🗄️ 服务库（Provider / 密钥 / 测试） > │  ← 原 Services Tab 移入
│  📚 知识库（文档 / 笔记）           > │
│  🔌 MCP 工具（本地 / 远程）         > │
├───────────────────────────────────────┤
│ 通用设置                              │
│  🎨 外观与主题                      > │
│  🛰️ 后台与权限                      > │  ← 前台服务/来电监听/电池/通知/邮箱日历授权
│  💬 对话默认参数                    > │  ← 历史数/温度/MaxTokens/Markdown
│  🔊 语音默认参数                    > │  ← 采样率/语速/音调
│  🔐 隐私与数据（导入/导出/清除）    > │
│  ℹ️ 关于                            > │
├───────────────────────────────────────┤
│  💬 首页   📡 订阅   🌿 生活   👤 我的 │
└───────────────────────────────────────┘
```

- **助手管理**：列出全部助手（被动+主动），开关启用、进入各助手配置、调整首页排序。
- **服务库**：完整 Provider 管理（增删改、测试连接、密钥），高级/开发者用户在此操作；消费端默认有预置可用配置（见 UniHelper.md §1.3 零配置）。
- **后台与权限**：集中收口所有系统授权——前台服务、来电状态监听、忽略电池优化、通知权限、邮箱授权（IMAP/OAuth）、日历授权、麦克风/相机/无障碍。

## 7. 主动式助手详设

每个助手统一结构：**能力 / 触发 / 产出记录 / 配置项 / 复用与新增 / 平台限制**。

### 7.1 📞 电话助手（通话翻译）

| 项 | 内容 |
|----|------|
| 能力 | 监听来电 → 自动进入通话翻译模式，双向逐句翻译并朗读；通话结束生成翻译记录 |
| 触发 | 事件触发：系统来电（去电可选） |
| 记录 | 通话翻译记录（双语逐句 transcript + 时长 + 联系人） |
| 配置 | 自动启动开关、默认语言对、白/黑名单、仅免提时启用、朗读音色 |
| 复用 | 复用 `ast/translate` 链路 + `agent_runtime` 通话模式 + 后台前台服务保活 |
| 新增 | 来电监听（CallScreening/PhoneState）、通话音频接入、通话内双向同传编排 |

> ⚠️ **平台限制（必须如实告知用户）**：普通运营商电话的对端音频，Android 现代版本**不允许**第三方 App 录制；iOS（CallKit）**完全不允许**。可行方案：
> - **方案 A（半双工·免提）**：通话开免提，用麦克风采集对方扬声器外放声 + 本机扬声器播报译文。可用但有回声/时序问题。
> - **方案 B（VoIP/网络通话）**：在 App 内置或对接的网络通话里做真双向同传（最干净，推荐主推场景）。
> - **方案 C（iOS 降级）**：iOS 仅做"来电提醒 + 一键进入面对面/免提翻译"，不承诺自动接管运营商通话。
> 文档与产品文案据此分平台表述，不夸大。

```
┌── 通话翻译中 · 张三 02:14 ──┐
│ 对方(EN) Are we still on… │
│ 译   你 我们还约着吗？     │
│ 你(中) 是的，下午三点      │
│ 译 对方 Yes, 3 pm         │
│  🟢 同传中   [🔇] [挂断]   │
└────────────────────────────┘
```

### 7.2 📰 咨询助手（资讯订阅）

| 项 | 内容 |
|----|------|
| 能力 | 每日定时按用户偏好/任务，搜集全球资讯 → LLM 摘要去重 → 生成 digest → 推送 |
| 触发 | 定时（每日 N 次，用户设定时段）+ 可手动"现在更新" |
| 记录 | 每日资讯 digest（分主题、带来源链接、可追问） |
| 配置 | 订阅主题/关键词、来源（搜索/RSS/API）、推送时间、语言、条数、深度（标题/摘要/精读） |
| 复用 | `llm_openai`（摘要）、知识库（沉淀可选）、统一会话（追问"详细讲讲第 3 条"） |
| 新增 | 资讯源采集（WebSearch/RSS）、定时任务、digest 生成与去重 |

### 7.3 📅 日程管理助手

| 项 | 内容 |
|----|------|
| 能力 | 自然语言/语音添加日程，定时提醒；与系统日历双向同步（可选） |
| 触发 | 定时（到点提醒）+ 会话内创建（"明早八点提醒我开会"） |
| 记录 | 日程/提醒列表（过去/未来），完成状态 |
| 配置 | 默认提醒提前量、是否同步系统日历、重复规则、提醒方式 |
| 复用 | 统一会话创建、动态 Tab 日历视图、系统通知 |
| 新增 | 日历/事件存储、提醒调度、系统日历集成（或 **Google Calendar MCP**） |

### 7.4 📧 邮件助手

| 项 | 内容 |
|----|------|
| 能力 | 定时拉取邮箱，自动阅读最新未读 → 判定重要性 → 重要则主动推送提醒；可按用户要求起草/发送回复 |
| 触发 | 定时巡检 + 会话内指令（"帮我回复张总，说同意"） |
| 记录 | 邮件摘要、重要性标记、处理状态（已读/已提醒/已回复） |
| 配置 | 邮箱账户授权、巡检频率、重要性判定偏好、自动回复规则（仅起草/需确认/自动发）、签名 |
| 复用 | `llm_openai`（分析/起草）、统一会话（确认回复）、推送 |
| 新增 | 邮箱接入（IMAP/OAuth 或 **Gmail MCP**）、定时拉取、重要性判定、起草/发送 |

> 安全默认：**起草后需用户确认才发送**；自动发送为高级开关并明确告知风险。

### 7.5 💰 财务助手

| 项 | 内容 |
|----|------|
| 能力 | 记录每日开销与每月收支；月度统计；定制财务计划与每月合理开销建议 |
| 触发 | 会话/语音记账（"午饭 38 块"）、拍小票 OCR 记账、定时月报 |
| 记录 | 流水（收/支/分类/备注/时间）、月报、预算执行 |
| 配置 | 币种、分类体系、月预算（总额/分类）、月报推送时间 |
| 复用 | 多模态（拍小票 → OCR/Vision 提取金额分类）、`llm_openai`（分析建议）、动态 Tab 报表 |
| 新增 | 交易/预算存储、统计与图表、预算预警、计划生成 |


### 7.6 ❤️ 健康助手

| 项 | 内容 |
|----|------|
| 能力 | 汇总步数/睡眠/心率/饮水等健康数据，按用户目标主动提醒（久坐、喝水、作息），生成日/周健康小结 |

## 8. 支撑架构增量（让"主动式"成立）

主动助手共享一套设施，叠加在现有 `agent_runtime` 之上（不推翻）：

```
┌──────────────────────────────────────────────┐
│  Scheduler / Trigger Engine（调度·触发引擎）★新增 │
│   · 定时任务（cron 式：资讯/邮件巡检/月报）        │
│   · 事件触发（来电、到点提醒）                    │
│   · 跑在 agent_runtime 前台服务内，App 退后台仍执行 │
└───────────────┬──────────────────────────────┘
                │ 触发 → 调用对应助手编排（Orchestrator + 技能 + 工具）
┌───────────────▼──────────────────────────────┐
│  各助手编排（复用 LLM/STT/TTS/翻译/Vision/MCP）   │
└───────────────┬──────────────────────────────┘
                │ 产出
        ┌───────┴────────┬──────────────┐
        ▼                ▼              ▼
  Records 时间轴     Notification     回写各助手数据
  （动态 Tab）        系统推送         （日程/邮件/交易…）
```

- **调度引擎**落在原生 `agent_runtime` 前台服务（Android 前台服务保活；iOS 用 BGTaskScheduler + 静默推送，**注意 iOS 不保证精确定时**，需如实说明）。
- **触发器**：时间触发 + 事件触发（来电监听、到点）。
- **Records**：统一记录时间轴，喂给"动态 Tab"。
- **Notification**：各助手主动推送走系统通知 + 首页"需要你关注 / 今日安排"简报区。
- **隐私**：邮箱/财务/通话等敏感数据**默认本地存储**（`local_db` 加密），云同步为可选项。

## 9. 数据模型增量

在 [UniHelper.md §6](UniHelper.md) 的 conversations/attachments/skills/documents/embeddings/memories 之上，再加主动助手相关：

```sql
-- 助手实例（被动+主动统一登记，驱动首页简报汇报与"助手管理"）
CREATE TABLE assistants (
  id TEXT PRIMARY KEY, type TEXT,          -- chat|translate|phone|news|schedule|email|finance
  name TEXT, enabled INTEGER, sort_order INTEGER, config_json TEXT
);
-- 订阅/定时任务（"动态"订阅视图 + 调度引擎读取）
CREATE TABLE tasks (
  id TEXT PRIMARY KEY, assistant_id TEXT, kind TEXT,   -- scheduled|trigger
  schedule_cron TEXT, trigger_type TEXT,               -- incoming_call|time|...
  params_json TEXT, enabled INTEGER,
  next_run_at INTEGER, last_run_at INTEGER
);
-- 统一记录时间轴（"动态"时间线视图）
CREATE TABLE records (
  id TEXT PRIMARY KEY, assistant_id TEXT, task_id TEXT,
  type TEXT, title TEXT, summary TEXT, payload_json TEXT,
  occurred_at INTEGER, status TEXT                     -- new|notified|done|...
);
-- 日程/事件（日程助手）
CREATE TABLE events (
  id TEXT PRIMARY KEY, title TEXT, start_at INTEGER, end_at INTEGER,
  remind_at INTEGER, location TEXT, repeat_rule TEXT, source TEXT, done INTEGER
);
-- 邮件缓存（邮件助手）
CREATE TABLE emails (
  id TEXT PRIMARY KEY, account TEXT, message_id TEXT, subject TEXT,
  sender TEXT, received_at INTEGER, importance TEXT,   -- high|normal|low
  summary TEXT, action TEXT                            -- none|notified|drafted|replied
);
-- 财务（财务助手）
CREATE TABLE transactions (
  id TEXT PRIMARY KEY, kind TEXT, amount REAL, currency TEXT,  -- income|expense
  category TEXT, note TEXT, occurred_at INTEGER, source TEXT   -- manual|voice|ocr
);
CREATE TABLE budgets (
  id TEXT PRIMARY KEY, period TEXT, category TEXT, limit_amount REAL  -- 月度/分类预算
);
```

## 10. 助手与现有 Agent / 技能的关系

- 旧"Agent"（chat/translate/sts/ast 配置）**下沉为技术层**，被"助手"复用；用户在"我的 → Agent/技能配置"里管理（高级）。
- "助手(Assistant)"是面向用户的顶层概念：被动助手 = 一个技能 + 配置；主动助手 = 技能 + 调度任务 + 记录 + 推送。
- "服务库(Provider)"是底层能力池，助手按需引用，不再占据首屏。
